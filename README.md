# Бизнес-навигатор — Telegram-помощник для предпринимателей

Прототип трека 2 кейса «Альфа-Курс: знания в нужный момент», Hack&Change 2026. Отвечает по базе знаний «Альфа-Курса», уточняет вопросы, учитывает профиль бизнеса и рекомендует материалы. Есть семидневный маршрут, напоминания, налоговый календарь, финансовая модель с PDF, тренажёры и Telegram Mini App.

[Посмотреть презентацию проекта в PDF](business-navigator.pdf)

## 1. Что потребуется

- Docker Engine или Docker Desktop с **Docker Compose v2** и запущенным Docker daemon. В Windows используйте терминал WSL 2 с включённой интеграцией Docker Desktop. Команды ниже рассчитаны на Bash.
- Git для клонирования либо скачанный и распакованный ZIP репозитория.
- Исходная выгрузка организаторов `alfa_course_hackathon.backup`. Она не включена в репозиторий.
- Токен своего Telegram-бота и API-ключ Yandex AI Studio для всех ИИ-функций.
- Интернет для сборки образов и доступа к Telegram и Yandex AI Studio. Временный публичный HTTPS-адрес Mini App создаётся автоматически через Cloudflare.

Python, PostgreSQL и системные библиотеки отдельно устанавливать не нужно: они входят в Docker-образы.

## 2. Подготовка

Из терминала клонируйте проект и создайте локальный файл настроек:

```bash
git clone --branch main https://github.com/shierururu/ai-telegram-helper.git
cd ai-telegram-helper
mkdir -p data/private
cp env.example .env
```

Если проект уже скачан, перейдите в его корень и выполните последние две команды; существующий `.env` не перезаписывайте.

Поместите выгрузку в `data/private/alfa_course_hackathon.backup`. Импортёр принимает конкретный архив организаторов и проверяет его SHA-256:

```text
c9cd546ed3bfeefb98b162d6683bce9096bdb03ada84fd683431683c5c6dff0e
```

Другой дамп, распакованный SQL или изменённая выгрузка не подойдут.

Откройте `.env` в текстовом редакторе и заполните:

```dotenv
ALFA_TELEGRAM_BOT_TOKEN=ваш_токен_бота
ALFA_YANDEX_API_KEY=ваш_секретный_API_ключ
```

- **Telegram:** откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, сохраните выданный токен и имя созданного бота. Один токен должен использоваться только одним запущенным экземпляром приложения.
- **Yandex:** создайте API-ключ через интерфейс AI Studio по [официальной инструкции](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key). Вставьте секретное значение ключа, а не его ID. Ключ должен давать доступ к генерации и эмбеддингам; для интернет-поиска в «Помощи ИИ» нужен также доступ к поиску. Ключ, созданный стандартным способом через AI Studio, получает доступ к компонентам сервиса. При ручной настройке используйте роли и области доступа из инструкции.

Используются **DeepSeek V4.1 Flash** (`deepseek-v4.1-flash`), эмбеддинги `text-embeddings-v2-doc` / `text-embeddings-v2-query` и встроенный веб-поиск Yandex через `https://ai.api.cloud.yandex.net/v1`. Создавать агента или загружать промпты в консоль Yandex не нужно: приложение передаёт инструкции само.

Вызовы Yandex тарифицируются. Нужны действующий платёжный аккаунт, доступ к моделям и достаточные квоты. Векторизация начинается при первом запуске с ключом, даже до первого вопроса. Без `ALFA_YANDEX_API_KEY` доступны локальный поиск, профиль и напоминания; генерация ИИ и зависящие от неё функции недоступны.

## 3. Запуск бота одной командой

Из корня проекта:

```bash
docker compose up --build -d
```

Compose запускает PostgreSQL, согласует пароли служебных ролей с текущими настройками, применяет миграции, офлайн собирает корпус из выгрузки, затем запускает бот и worker для доставки уведомлений. Миграции автоматически создают и обновляют таблицы; запускать SQL вручную не нужно. Текущая последняя ревизия — `0006_weekly_summary`.

Одноразовый сервис `database-roles` создаёт отсутствующие роли и обновляет пароли `alfa_migrator`, `alfa_bot` и `alfa_worker` перед миграциями, в том числе для существующего тома базы. Используются переменные `ALFA_MIGRATOR_DB_PASSWORD`, `ALFA_BOT_DB_PASSWORD` и `ALFA_WORKER_DB_PASSWORD` из настроек Compose (из `.env` либо значения по умолчанию). Данные сохраняются. Сервис подключается через общий с PostgreSQL локальный Unix-сокет; административный доступ не передаётся боту и worker. Пароль администратора `postgres` этим шагом не меняется.

Проверьте запуск:

```bash
docker compose ps -a
docker compose logs --tail=80 bot worker migrate prepare
```

Ожидаемый результат: `db` — healthy, `bot` и `worker` — Up; одноразовые `database-roles`, `migrate`, `corpus-permissions` и `prepare` завершаются с кодом 0. В логах бота появляется `bot_started`. После этого откройте **своего созданного бота** в Telegram и отправьте `/start`.

При первом запуске семантический индекс строится в фоне. Пока он не готов, работает BM25; `semantic=False` в стартовом логе само по себе не означает ошибку. Индекс сохраняется в Docker-томе и переиспользуется.

## 4. Mini App запускается автоматически

Команда из пункта 3 запускает также веб-сервер Mini App и сервис `tunnel` с Cloudflare Quick Tunnel. Устанавливать `cloudflared`, открывать отдельный терминал и копировать адрес в `.env` не нужно:

```bash
docker compose up --build -d
```

Бот получает временный HTTPS-адрес туннеля автоматически и настраивает кнопку меню **«Навигатор»**. Открыть Mini App можно этой кнопкой или через **«📱 Мини-апп»** в чате. Настройки в BotFather не требуются. Если запуск туннеля ещё идёт, подождите появления `webapp_public_url=https://…trycloudflare.com` в логах бота:

```bash
docker compose logs --tail=80 bot tunnel
curl --fail http://127.0.0.1:8080/healthz
```

Локальная проверка возвращает `ok`. Для проверки внешнего доступа откройте адрес из `webapp_public_url` с добавлением `/healthz`: ответ также должен быть `ok`. Внешний браузер без Telegram-подписи не авторизован в API: ответ 401 в таком случае ожидаем.

При пересоздании туннеля публичный адрес меняется. Бот отслеживает его и обновляет кнопку меню и новые ссылки Mini App без перезапуска; ранее отправленные ссылки могут устареть — откройте приложение через меню или запросите новую кнопку в чате. При временной недоступности Cloudflare чат-бот продолжает работать и повторяет попытки подключения.

Quick Tunnel требует исходящего доступа к Cloudflare и предназначен для разработки и демонстрации; его доступность не гарантируется. Для постоянного размещения можно задать свой стабильный `ALFA_WEBAPP_URL=https://…` в `.env` и направить этот домен на веб-сервер бота (`127.0.0.1:8080`). Явно заданный адрес имеет приоритет над автоматическим. Подробности и ограничения — в [документации Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## 5. Сценарий проверки организаторами

Используйте вымышленные сведения о бизнесе, без реальных персональных данных.

1. **Знакомство и профиль.** `/start` → пройдите вопросы или пропустите их. В «👤 Профиль» проверьте и измените сведения.
2. **Консультация.** «Что такое франшиза?» → ответ по базе и ссылки на материалы. «Я ИП на УСН, у меня кофейня. Как найти клиентов?» → учёт профиля. Кнопка «Объясни проще» упрощает полученный ответ.
3. **Уточнение и отсутствие ответа.** «Помоги с бизнесом» → уточнение; вопрос о теме, которой нет в базе, → сообщение об отсутствии ответа. Отдельная «Помощь ИИ» явно обозначает ответы вне базы и может использовать интернет-поиск.
4. **Рекомендации.** В консультации проверьте карточку платного курса или курса по «Подписке Курс+» и переход к странице. Показываются краткая польза и ссылка, содержание платных уроков не раскрывается. «Курс+» отображается без цены. В A/B-варианте A курс находится в списке материалов, в B — в отдельном блоке без дублирования.
5. **Напоминания.** «🔔 Напоминания» → создайте разовое напоминание на ближайшее время, выберите город/часовой пояс и подтвердите дату. Дождитесь сообщения. Через управление напоминанием измените частоту на еженедельную, затем отключите его.
6. **Маршрут и уведомления.** «🧭 Мой маршрут» → цель, город, время → предпросмотр семи дней → подтверждение запуска. Первый шаг запланирован на завтра; план можно остановить. «⚙️ Настройки» или `/settings` → смена города, включение/отключение итогов недели, тихие часы и общий лимит уведомлений. Итоги приходят только по согласию, по воскресеньям в 19:00 в выбранном часовом поясе.
7. **Инструменты.** «🧰 Инструменты» → налоговый календарь, тренажёры и финмодель. В финмодели введите показатели и скачайте PDF. В Mini App проверьте те же разделы, консультацию, профиль и напоминания.
8. **Сохранение данных.** Выполните `docker compose restart bot worker`. Профиль, маршрут и напоминания должны сохраниться. Для просмотра аналитики добавьте свой Telegram ID в `ALFA_ADMIN_IDS`, примените `docker compose up -d bot` и вызовите `/stats` и `/export`.

## 6. Дополнительные настройки

Настройки задаются в `.env`. После изменения выполните `docker compose up -d`: обычный `restart` не обновляет переменные окружения контейнера.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ALFA_SOURCE_ARCHIVE` | `./data/private/alfa_course_hackathon.backup` | Путь к исходному архиву на хосте |
| `ALFA_YANDEX_FOLDER_ID` | определяется через API | ID каталога Yandex Cloud; можно указать явно, если автоматическое определение не работает |
| `ALFA_WEBAPP_URL` | автоматически через туннель | Свой стабильный HTTPS-адрес Mini App; имеет приоритет над временным |
| `ALFA_ADMIN_IDS` | пусто | Telegram ID администраторов через запятую для `/stats` и `/export` |
| `ALFA_AB_PAID_OFFER` | `true` | Включение A/B-теста подачи курса; `false` оставляет вариант A |
| `ALFA_YANDEX_TIMEOUT_SECONDS` | `20` | Тайм-аут одного HTTP-вызова модели, секунды |
| `ALFA_ANSWER_DEADLINE_SECONDS` | `25` | Общий дедлайн консультации, секунды; допустимо 5–300 |
| `ALFA_YANDEX_REASONING_EFFORT` | `none` | Дополнительное рассуждение модели; `none` сокращает задержку |
| `ALFA_WORKER_POLL_INTERVAL_SECONDS` | `5` | Интервал проверки очереди уведомлений, секунды |
| `ALFA_LOG_LEVEL` | `INFO` | Уровень логирования |

PostgreSQL доступен только внутри Compose на порту `5432`. На хост опубликован `127.0.0.1:8080` для Mini App. Боту не нужен входящий публичный порт: он получает сообщения через polling. Бот и worker требуют исходящий HTTPS к Telegram, ИИ-функции — к Yandex. HTTPS-туннель Mini App запускается автоматически; ему нужен исходящий доступ к Cloudflare.

## 7. Остановка, обновление и диагностика

```bash
# Остановка с сохранением данных
docker compose down

# Логи проблемного сервиса
docker compose logs --tail=100 bot worker migrate prepare
```

Перед обновлением существующей базы сделайте резервную копию:

```bash
mkdir -p data/private
docker compose exec -T db pg_dump -U postgres -d alfa_course -Fc > data/private/runtime-before-upgrade.backup
```

Затем обновите исходники и пересоберите контейнеры:

```bash
git pull --ff-only origin main
docker compose up --build -d
```

База, корпус и индекс хранятся в именованных Docker-томах. **Не используйте `docker compose down -v`**, если хотите сохранить данные. Если ранее запускали с `-p имя`, используйте тот же `-p имя` во всех командах Compose, иначе получите отдельное окружение.

| Проблема | Что проверить |
| --- | --- |
| Docker недоступен | Запущен Docker daemon; в WSL включена интеграция Docker Desktop |
| `prepare` завершился с ошибкой | Архив существует по указанному пути, доступен для чтения и совпадает с исходной выгрузкой; подробности — `docker compose logs prepare` |
| `migrate` завершился с ошибкой | Посмотрите `docker compose logs migrate db`; проверьте также `docker compose logs database-roles`: согласование паролей должно завершиться с кодом 0 |
| `TelegramConflictError` | Остановите другой экземпляр бота с этим токеном |
| Ошибка Yandex, нет ответа ИИ | Проверьте секретный ключ, каталог, права, срок действия, квоты и платёжный аккаунт; подробности — в логах `bot` |
| Mini App не открывается, ошибка 502 или сброс соединения | Дождитесь `webapp_started` и `webapp_public_url` (при автоматическом адресе), проверьте локальный `/healthz` и `docker compose logs tunnel`; после изменения `.env` пересоздайте `bot` командой `docker compose up -d bot` |

## Архитектура и ограничения

Модульный Python-бэкенд: `aiogram` обслуживает Telegram, `aiohttp` — Mini App; оба используют общие прикладные сервисы и PostgreSQL. Отдельный worker отправляет уведомления. Офлайн-импортёр готовит корпус; поиск сочетает BM25 с русским стеммингом и семантические векторы Yandex. DeepSeek понимает запрос и формирует ответ по найденным фрагментам; код проверяет источники. Версии зависимостей закреплены в `pyproject.toml`, `uv.lock` и `requirements*.txt`; Docker устанавливает зависимости с проверкой хешей.

- Корпус содержит 918 карточек: 915 бесплатных, 1 платную и 2 подписочные. Вложения DOCX/PDF из ссылок не скачиваются. Используется схема корпуса v3, политика допуска v4.
- Выгрузка, производный корпус и ключи не включены в Git и Docker-образ. Во внешние ИИ-запросы допускаются публичные фрагменты бесплатных материалов и публичные карточки; подробное содержание платных уроков исключено. Маскирование пользовательских данных не гарантирует распознавания всех чувствительных сведений.
- Качество ответа ограничено покрытием базы. При тайм-ауте или ошибке генерации бот сообщает о проблеме. Ответы отдельной «Помощи ИИ» и налоговый календарь требуют самостоятельной проверки; календарь рассчитан на 2026 год.
- Диалоговые черновики и история переписки сбрасываются при перезапуске. Профиль, маршруты, напоминания и события хранятся в БД.
- A/B-тест измеряет переходы к курсам, а не покупки. Доказанного роста продаж пока нет.
